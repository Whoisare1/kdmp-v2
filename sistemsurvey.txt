PENJELASAN ALUR SISTEM /SURVEI (MODUL SURVEI)

Sistem survei pada aplikasi KDMP dirancang untuk memudahkan manajemen jadwal survei dan pengisian data di lapangan. Alur sistemnya terbagi menjadi dua bagian utama: Bagian Admin/Manajer dan Bagian Publik (Petugas Lapangan).

1. Manajemen Sesi (Bagian Admin/Manajer)
   - Route: `/survei/sesi` dan `/survei/dashboard`
   - Controller: `SesiSurveiController`
   - Alur Kerja: Manajer (pengguna yang sudah login) membuat "Sesi Survei" baru dengan menentukan wilayah/desa, bulan, tahun, dan siapa petugasnya. 
   - Setelah sesi berhasil dibuat, sistem akan men-generate sebuah token publik (link unik). Link inilah yang nantinya dibagikan ke petugas di lapangan melalui WhatsApp atau email.

2. Pengisian Survei (Bagian Publik / Petugas Lapangan)
   - Route: `/survei/isi/{token}`
   - Controller Utama: `PublicSurveiController`, `PublicSesi1Controller`, `PublicSesi2Controller`, dst.
   - Alur Kerja: Petugas membuka link survei publik tanpa perlu login. Proses pengisian survei dipecah menjadi 4 tahapan sistematis:
     * Sesi 1: Data Demografi Desa (Mendata narasumber dan data kependudukan).
     * Sesi 2: Potensi Produksi Desa (Mendata produksi komoditas di desa tersebut).
     * Sesi 3: Standar Konsumsi Komoditas.
     * Sesi 4: Pemenuhan & Harga Komoditas.
   - Setiap tahapan memiliki opsi untuk menyimpan sebagai Draft (sementara) sebelum akhirnya diselesaikan (Selesaikan Sesi).

3. Letak File Utama Sistem Survei:
   - Logic / Controller: `app/Http/Controllers/Survei/`
   - Tampilan / Views: `resources/views/survei/` (Dipecah per sesi seperti folder sesi1, sesi2, public, dll).
   - Pengaturan URL / Routes: `routes/web.php` (di bagian M1 - Survey).

TEKNOLOGI LOKASI YANG DIGUNAKAN (/FITUR)
Aplikasi di dalam folder ini tidak menggunakan Google Maps yang berbayar, melainkan mengkombinasikan teknologi berikut:
- Nominatim + OpenStreetMap (OSM): Berfungsi sebagai mesin *Geocoding* gratis. Digunakan untuk mengubah teks alamat yang diketik responden menjadi titik koordinat (Latitude & Longitude) pusat desa/wilayah tersebut.
- Browser Geolocation API: Mengambil koordinat sinyal GPS perangkat (HP) pengguna.
- Rumus Haversine (PHP): Menghitung jarak melengkung antara koordinat rumah asli vs koordinat OpenStreetMap di server.

ALUR CARA KERJA APLIKASI DI DALAM FOLDER /FITUR (Jika Dijalankan)
Aplikasi mini ini berfungsi sebagai purwarupa (prototipe) untuk Verifikasi Titik Lokasi Rumah Responden secara otomatis. Jika dijalankan, alurnya adalah:

1. Layar 1 (Identitas) 
   Responden diminta memasukkan Nama dan Nomor HP secara sederhana.
   
2. Layar 2 (Alamat & Geocoding)
   Responden memasukkan alamat rumah mereka. Di balik layar, sistem akan langsung mengirim alamat ini ke satelit peta OpenStreetMap (Nominatim) untuk mendapatkan titik koordinat referensi desa tersebut. Jika alamat spesifik tidak ditemukan, sistem otomatis mencari area yang lebih luas (misalnya level kecamatan) agar pasti ketemu.

3. Layar 3 (Akses GPS Otomatis) 
   Browser akan meminta izin lokasi (Pop-up "Allow Location"). 
   - Sistem akan mencoba menyedot sinyal GPS paling akurat dari satelit selama 20 detik.
   - Jika responden sedang berada di dalam ruangan (sinyal jelek), sistem tidak akan error, melainkan otomatis menggunakan pelacakan via sinyal Wi-Fi/Menara Seluler terdekat (akurasi rendah) selama 30 detik agar lokasi pasti didapat.

4. Validasi Anti-Blokir (Di Server)
   Setelah koordinat asli HP responden didapat, server akan menggunakan Rumus Haversine untuk menghitung jarak antara rumah asli (GPS) dengan pusat desa (OpenStreetMap).
   - Sistem ini sangat "ramah responden". Meskipun jaraknya melenceng jauh (> 5 KM), sistem TIDAK AKAN menolak formulir tersebut.
   - Responden akan selalu melihat layar "Sukses!". Namun di database admin, datanya akan ditandai dengan status `PERLU_TINJAUAN_MANUAL`. Jika jaraknya dekat, maka ditandai `VALIDASI_BERHASIL`.
