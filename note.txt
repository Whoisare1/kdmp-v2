# TUTORIAL

## KONSEP DASAR: CARA MAINNYA
Jangan langsung gabungkan fitur yang baru kamu buat ke branch `main`. Selalu gunakan branch perantara (biasanya bernama `developer` atau `staging`) sebagai tempat berkumpulnya semua fitur untuk dites terlebih dahulu.

Ibaratnya:
- Branch fitur (`feature/finance`, `feature/pembelian`, dll) = Bahan-bahan masakan.
- Branch `developer` = Gelas tempat mengaduk dan menyatukan semua bahan.
- Branch `main` = Gelas yang sudah sempurna dan siap disajikan ke pelanggan.

---

## LANGKAH-LANGKAH PENGGABUNGAN (MERGE)

### 1. Pindah ke Branch Wadah (Developer)
Pastikan kamu masuk ke branch developer dan pastikan branch ini adalah yang paling update.
```bash
git checkout developer
git pull origin developer
```

### 2. Gabungkan Branch Fitur Kamu
Mulai gabungkan branch fiturmu satu per satu ke dalam wadah developer ini.
```bash
git merge feature/nama-fitur-kamu
```
Jika muncul pesan **"Already up to date"**, artinya fiturmu SUDAH BERHASIL masuk ke dalam branch developer. Karena semua fitur sudah masuk ke satu wadah, kamu **tidak perlu pindah-pindah branch lagi** untuk mengetes fitur A atau fitur B. Semuanya sudah kumpul di `developer`.

---

## BAGAIMANA JIKA TERJADI ERROR / CONFLICT?

Terkadang saat mencoba `git merge`, kamu akan mendapat error **CONFLICT**. Ini terjadi karena dua orang yang berbeda mengubah baris kode yang sama di file yang sama.

Jika kamu kena pesan error seperti ini:
`error: you need to resolve your current index first`
Itu artinya Git kamu sedang *nyangkut* di tengah-tengah proses merge yang gagal. Git mengunci aplikasimu dan tidak akan membiarkanmu pindah branch sebelum urusan ini selesai!

**Solusi 1: Jurus Kabur (Paling Aman)**
Jika kamu bingung, tidak paham kode yang bentrok (karena itu pekerjaan orang lain), dan takut aplikasinya malah rusak, BATALKAN proses mergenya seketika dengan perintah:
```bash
git merge --abort
```
*(Perintah ini akan menyapu bersih proses merge yang nyangkut dan mengembalikan kodemu bersih seperti semula).*
Setelah aman, minta tolong pembuat fitur tersebut untuk memperbaiki conflict-nya.

**Solusi 2: Hadapi dan Selesaikan secara Manual**
Jika kamu membuka file yang error, kamu akan melihat kode aneh pembatas seperti `<<<<<<< HEAD`, `=======`, dan `>>>>>>>`.
- **Hati-hati:** Jangan asal menghapus salah satu sisi kode! Kadang, kedua sisi kode itu (misalnya fungsi A dari branch lama dan fungsi B dari branch baru) sama-sama dibutuhkan.
- Gabungkan kodenya dengan baik (misal, jadikan satu di dalam class yang sama).
- Hapus tanda-tanda kurung sikunya (`<<<<<<<`, dsb).
- Simpan file, lalu beri tahu Git bahwa kamu sudah menyelesaikannya:
```bash
git add nama-file-yang-conflict.php
git commit -m "Menyelesaikan conflict di nama file"
```

---

## LANGKAH TERAKHIR: TESTING BERSAMA-SAMA

Setelah semua branch fitur sukses di-merge tanpa sisa conflict, hal terpenting adalah **Mentes Aplikasinya**.

Karena kamu sudah berada di `developer` yang berisi gabungan seluruh fitur, kamu harus menyiapkan ulang aplikasinya agar sinkron:

1. Reset Database & Isi Data Palsu (Penting untuk Laravel):
```bash
php artisan migrate:fresh
php artisan db:seed
```
2. Jalankan server backend dan frontend-nya:
```bash
php artisan serve
npm run dev
```
3. Buka browser, kelilingi semua menunya. Pastikan fitur A tidak merusak fitur B.
4. Jika sudah dites keliling dan 100% aman terkendali, barulah kodenya kita simpan ke server bersama-sama:
```bash
git push origin developer
```
Baru setelah itu semua aman, kode siap dibawa ke branch `main`.
